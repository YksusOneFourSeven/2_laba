# Краткий регламент выпуска DOC-17

## 1. Роли решения

- `teacher_release` — владелец выпуска, принимает решение GO/STOP в контрольных точках.
- `student_engineer` — выполняет развертывание, миграцию и возврат.
- `student_tester` — подтверждает результаты обязательных проверок.
- `teacher_process` — владелец приёмки процесса.
- `student_support` — отслеживает обращения и сообщает об отклонениях.

Текущее решение — STOP; настоящий регламент применяется только после выполнения условий [`release_decision.md`](release_decision.md).

## 2. Предварительные условия до окна

Должны быть выполнены все пункты:

1. Получен архив `app-1.5.0-rc1.zip`; вычисленный хеш записан и связан с результатами тестов.
2. T01, T02 и T03 относятся к тому же хешу кандидата и имеют доказательства.
3. T04 завершён успешно: контрольный набор восстановлен, RTO ≤20 минут, RPO ≤15 минут.
4. T05 завершён успешно: 20 одновременных операторов, 1000 заявок, успех ≥99%, p95 ≤800 мс с учётом ошибок.
5. Доступны Linux x64, Python 3.11/3.12, PostgreSQL 15/16 и минимум 2048 МиБ свободного места.
6. Установлены обязательные параметры `APP_PORT`, `DB_HOST`, `DB_NAME`, `ATTACHMENTS_DIR`; секреты доставлены отдельно.
7. Каталог вложений и БД доступны, а резервная копия `B-1755` включает БД, вложения и конфигурацию.
8. Исправленный фрагмент инструкции из [`documentation_changes.md`](documentation_changes.md) передан пользователям/поддержке.
9. `category_required` не включается в этом окне. Если её включение необходимо, заранее утверждён отдельный план совместимости и преобразования данных при возврате.

`teacher_release` открывает окно только после проверки этих доказательств; наличие плана без результата условие не закрывает.

## 3. Временной план окна 18:00–18:30

| Время/предел | Действие и контрольная точка | Решение |
|---|---|---|
| до 18:00 | проверить предварительные условия, хеш, резервную копию, доступы и свободное место | при любом пробеле — окно не открывать |
| 18:00 | закрыть запись; зафиксировать начало окна и исходное состояние S1 | несоответствие — STOP |
| после 18:00 | развернуть кандидат и выполнить M015 один раз | результат сверить по журналу миграций; не повторять вслепую |
| до открытия записи | проверить запуск, подключение к БД, схему S2, создание/чтение, доступ, идемпотентность, назначение технику и сохранность вложений | только все успешные проверки позволяют открыть запись |
| **18:22** | последняя контрольная точка возврата: `18:30 − 8 минут` | если запись ещё не открыта и готовность не доказана — `teacher_release` запускает возврат |
| не позднее 18:30 | завершить возврат либо зафиксировать успешное внедрение | превышение окна — инцидент и эскалация владельцу выпуска |

## 4. Критерии немедленной остановки

- дефект доступа, потеря/расхождение данных или создание дубля;
- неуспешная/неопределённая M015 либо неизвестное состояние журнала миграций;
- несоответствие списка и карточки;
- недоступность БД или каталога вложений;
- отсутствие обязательного доказательства либо невозможность закончить проверки до 18:22;
- необходимость включить `category_required` без согласованного плана возврата данных.

Решение об остановке принимает `teacher_release`; любой исполнитель обязан сообщить основание немедленно.

## 5. Возврат до открытия записи

1. Не открывать запись пользователям.
2. Зафиксировать причину и состояние M015 по журналу миграций.
3. Остановить кандидат 1.5.0-rc1.
4. Вернуть приложение 1.4.2. Оно может читать S2, пока `category_required` не включена и несовместимые новые записи не появились.
5. Проверить доступность БД, заявок и вложений, затем открыть прежнюю версию только после решения `teacher_release`.
6. Завершить последовательность в пределах 8 минут и не позднее 18:30.

Повтор M015 выполняется только после установления её фактического результата.

## 6. После открытия записи

После открытия записи могли появиться новые данные. Их совместимость со старой версией не подтверждена, особенно после возможного включения `category_required`. Поэтому автоматическое восстановление старой копии запрещено: оно может нарушить RPO и потерять новые данные. Нужно остановить дальнейшие изменения, сохранить текущее состояние и разработать новый согласованный план преобразования/возврата с оценкой RTO/RPO; решение принимает `teacher_release` совместно с `teacher_process`.
